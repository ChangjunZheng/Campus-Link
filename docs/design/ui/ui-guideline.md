## 2. 设计定位（信息架构原则）

**产品形态**：Web 网站优先（桌面 + 响应式），**内容型垂直社区**，单校范围（[技术方案](../tech-design.md) 第 1 节）。

由此确定的**三条硬约束**：

1. **信息密度优先，列表页是主战场**。用户 80% 的时间在扫列表，判定列表页好坏的标准是"一屏能扫几条、每条能否看清是否值得点"，不是视觉张力；
2. **内容为主体，装饰为零**。不做插画、不做渐变、不做大圆角卡片堆叠——这些会挤掉列表的信息密度；
3. **导航服从"版块少、层级浅"**。当前 6 个固定版块（`qna` / `resources` / `interview` / `contest` / `course` / `chat`，见 [PRD](../../requirements/prd.md) F-FORUM-001）。

| 决策 | 结论 | 理由 |
|---|---|---|
| 顶栏平铺 6 版块 | ✅ **保留现状** | 6 个固定版块顶栏放得下；`overflow-x: auto` 已处理窄屏 |
| 首页版块卡片矩阵 | ✅ **保留现状** | `el-col xs=24 / sm=12 / md=8` 响应式已就位 |
| **左侧版块导航栏** | ❌ **本阶段不做** | 左侧栏的价值在"版块多 + 有二级导航（我的 / 收藏 / 设置）"。6 个版块 + 试点期流量撑不起，且与 [CR-022](../../change-log.md) 最小 MVP 相悖。**重新评估的触发条件**：版块数 > 10，或个人中心落地后需要常驻二级导航 |
| **面包屑** | ⚠️ **建议补（P1）** | 现状从首页 → 版块 → 帖子三级跳转后，页面内没有任何"我在哪"的信息 |

这些不是审美问题，是**同一件事在多处写法不同**——根因是**缺设计令牌层**（§1 已核实无任何全局样式文件）。

| # | 现象 | 位置 | 处置 |
|---|---|---|---|

| 6 | **详情页正文撑满 1080px** | `PostDetailView.vue` `.markdown-body` | 阅读列宽收窄至 760px（§6） |

## 4. 设计令牌建议

### 4.1 落地方式

**新增 `frontend/src/styles/tokens.css`，在 `main.ts` 中一次性引入**（纯 CSS 自定义属性，**不引入任何构建依赖**）。

**与 Element Plus 的关系**：不另起一套平行体系。Element Plus 已用 `--el-*` 定义主色、圆角基数等，**已有的一律复用，只补它没有的**（间距刻度、阅读列宽、元信息文本色、分隔线色）。必要时以映射方式覆写，例如 `--el-text-color-regular: var(--cl-text-regular)`。

### 4.3 对比度实测（WCAG 2.1 AA）

按 WCAG 相对亮度公式计算（数值经脚本复核，非目测）：

| 前景色 | on `#f5f6f8`（页面底） | on `#ffffff`（卡片） | 结论 |
|---|---|---|---|
| `#303133` | 12.04:1 | 13.02:1 | ✅ 达标 |
| `#606266` | **5.65:1** | **6.11:1** | ✅ 达标（**元信息应改用此色**） |
| `#909399` | **2.85:1** | **3.08:1** | ❌ **不达标**——现状 `.post-meta` 用的就是它 |
| `#a8abb2` | 2.13:1 | 2.30:1 | ❌ 仅可用于占位符 / 禁用态 |
| `#409eff` | **2.57:1** | **2.78:1** | ❌ 一般不达标——见下 |
| `#337ecc`（Element Plus `primary-dark-2`） | 3.89:1 | 4.20:1 | ⚠️ 仍差一点 |
| **`#1a6fc4`** | **4.72:1** | **5.10:1** | ✅ 达标（**建议作正文链接色**） |
| `#185FA5` | 6.03:1 | 6.52:1 | ✅ 达标（更保守的选择） |

**由此得到两条硬约定**：

1. **元信息、摘要等 ≤14px 文本不得用 `#909399`**，用 `#606266`；
2. **`#409eff` 不得作为小号文字色**。现状 `#409eff` 被用在列表标题 hover、版块链接（13px）等多处——按 AA 口径**不达标**（正常文本要求 ≥ 4.5:1；仅 ≥18.66px 粗体或 ≥24px 时可放宽至 3:1）。**保留 `#409eff` 给按钮底色，文字链接改用 `#1a6fc4`，或在链接上叠加下划线以不依赖颜色区分**。

## 5. 组件与交互约定（W-03 补偿①）

### 5.1 列表项（`PostListItem.vue`，建议新增）

**首页与版块页必须共用同一个组件**，消除 §3 第 3 项。

结构与层级（自上而下）：

| 层 | 内容 | 规格 |
|---|---|---|
| 1 | 标题 | `--cl-font-title-sm` / **500** / 单行截断；不用彩色，hover 才变色 |
| 2 | 摘要 | `--cl-font-sm` / `--cl-text-regular` / **最多 2 行截断**（`-webkit-line-clamp: 2`）；由服务端截断到 120 字，前端只做溢出省略 |
| 3 | 元信息 | `--cl-font-caption` / `--cl-text-meta`；依次为 作者 · 回复数 · 时间；**「最后回复时间」右对齐** |
| — | 条目内边距 | **`--cl-space-3`（12px）**，两页统一 |
| — | 分隔 | `1px solid var(--cl-border-divider)`，**最后一项无分隔** |

> **摘要不要单行 `nowrap`**（现状 `BoardView.vue` 即如此）：服务端已把正文截到 120 字，再压成一行等于白截。2 行是"够判断是否值得点"的最小空间。
>
> **「最后回复时间」为何单列**：论坛的核心问题是"有没有新回复"，不是"什么时候发的"。

### 5.2 四态约定

**每个数据页面必须显式处理四种状态**，且用**不同**的载体——这是现状做得相对完整、应固化为约定的一部分：

| 状态 | 载体 | 现状实现 | 约定 |
|---|---|---|---|
| 加载中 | 列表用 `v-loading`；**详情首屏用 `el-skeleton`** | ✅ 已实现（`HomeView` / `BoardView` / `PostDetailView`） | 骨架屏优于转圈；详情页必须用骨架屏，避免布局跳动 |
| 空 | `el-empty` + **行动引导文案** | ✅ 已实现（"还没有帖子，来发第一帖吧"） | 文案必须给出下一步动作，不能只写"暂无数据" |
| 错误 | 列表页内联 `el-alert type="error"`；**操作类用 `ElMessage.error`** | ✅ 已实现（`BoardView` 内联 alert） | 页面级失败用内联（不遮挡内容），操作级失败用消息提示 |
| **不存在** | **业务码 `3001` → 专用 `el-result`** | ✅ 已实现（`PostDetailView`） | **不复用通用错误态**——"帖子不存在"与"加载失败"对用户是两个不同的世界，前者不该重试、应给"回首页" |

> 这一条是**现状已经做对的**，写进来是为了**防止后续退化**：[api/README.md](../api/README.md) §6.3 已注明 `1002` / `1003` / `1004` 三类响应进不了 OpenAPI 快照、须读文字约定——错误态的实现依据是文字约定，不是快照。

### 5.3 表单与草稿

- **提交失败不得清空已输入内容**（现状 `PostDetailView` / `PublishView` 均已满足——失败时保留 `replyMd` / `form`）；
- 提交中按钮必须进 `loading` 且禁二次提交（现状已满足）；
- 校验顺序：**前端先做非空校验给出提示，最终以后端校验为准**（后端 `1001` 为参数错误）。

### 5.4 分页

- **参数口径：`page` / `size`**（`page` 从 1 起）。这是本 Sprint 确认为实现口径的写法，技术方案 §5 已同步（原 `pageNum` / `pageSize` 口径作废，见 [sprint-2-design.md](../../development/sprint-2-design.md) §6 的 D-6）；
- 每页条数：**首页 10、版块页 20、楼层 20**（现状值，保留）；
- 列表页用 `layout="prev, pager, next"` 居中；**仅在 `total > size` 时渲染**分页器（现状已满足）。

### 5.5 时间显示

- 传输：ISO-8601 UTC；展示：前端本地化（`utils/time.ts` 的 `formatTime`，输出 `YYYY-MM-DD HH:mm`）；
- **建议（P1）**：列表页改用**相对时间**（`3 小时前` / `昨天`），详情页保留绝对时间。列表页的绝对时间对扫读帮助有限，而"多久之前"直接回答"这条热不热"。

### 5.6 Markdown 正文与代码高亮

**这是 ADR-005 的硬边界，前端不得越界**：

| 项 | 约定 |
|---|---|
| 渲染位置 | **只在服务端一个执行点**（`common/markdown`）。发布时渲染 `content_html` 落库，请求时**零渲染** |
| XSS 防线 | 在服务端的 `MarkdownRenderer`（flexmark + jsoup 白名单），**不在前端**。前端只负责 `v-html` 呈现 |
| **禁止** | 前端二次渲染 Markdown 做正文展示；前端自行拼接 HTML |
| 代码高亮 | **由前端 `highlight.js` 完成**（服务端只输出 `<pre><code class="language-*">`，避免为 hljs 的样式类扩大白名单）——**当前未实现，属欠账** |
| 样式归属 | `.markdown-body` 必须**提为全局样式**（现状写在 `PostDetailView.vue` 的 `scoped` 中，**发帖预览无法复用**） |

> 代码块样式最低要求：`background: var(--cl-bg-code)`、`--cl-radius-sm`、`overflow-x: auto`、行内 `code` 用等宽字体；**长代码必须横向滚动而非换行**。

### 5.7 鉴权与跳转

- 受保护路由（`/publish`、`/notifications`）由路由守卫统一拦截，未登录跳 `/login?redirect=<原路径>`（现状已实现）；
- 页面内触发受保护操作（如发回复）**必须二次判断登录态**并携带回跳，不能只依赖路由守卫——因为详情页本身是公开的；
- **前端显隐只是体验，不是安全边界**：真正的鉴权在后端。当前 `SecurityConfig` 仍为 `permitAll()`（**N-4 敞口**，归口 A3-9），受保护端点靠**手写校验 + 401 单测**顶住——前端**不得**因"后端没拦"而省略登录态判断，也不得因"前端拦了"而认为安全。

## 6. 排版与阅读

| 项 | 约定 | 现状 |
|---|---|---|
| 列表页容器宽 | `--cl-container`（1080px） | ✅ 一致 |
| **详情页正文列宽** | **`--cl-reading`（760px）居中** | ❌ 撑满 1080px——每行约 60+ 中文字符，长文需来回扫视 |

> 760px 的依据：中文正文的舒适行宽约 **35~45 个中文字符**，按 14px 字号测算约 700~780px。`--cl-reading` 取 760px，落在区间中部。

## 7. 响应式

[PRD](../../requirements/prd.md) §4 是**基线指标**："移动端——响应式适配，**浏览 / 发帖 / 回复核心链路可用**"。按 [PRD](../../requirements/prd.md) §5.1 检查清单，此项需**逐页走查**确认（W-03 补偿③）。

断点沿用 Element Plus 栅格：`xs <768` / `sm ≥768` / `md ≥992` / `lg ≥1200`。

| 项 | 现状 | 约定 |
|---|---|---|
| 版块卡片 | `xs=24 / sm=12 / md=8` | ✅ 保留 |
| 顶栏版块导航 | `overflow-x: auto` | ✅ 保留（窄屏横向滚动优于折行） |
| **顶栏搜索框** | 固定 `200px` | ⚠️ **窄屏（<768）隐藏或折叠为图标**——否则挤压用户菜单，顶栏必然溢出 |
| 发帖正文框 | `:rows="14"` | ⚠️ 窄屏降到 8 行左右，避免一屏放不下一篇文 |
| 回复框 | `:rows="6"` | ⚠️ 窄屏降到 4 行 |
| 详情页正文 | 撑满 | ⚠️ 窄屏自动等于全宽（`--cl-reading` 需配 `max-width`，不能写死宽度） |

> **实测要求**：本节所有 ⚠️ 项**必须走查确认**，不能以"用了 el-col 响应式"推定合格。走查属 W-03 补偿③，**当前未执行**。
