## 1. 测试范围

**测什么**：本轮覆盖的功能清单（对应 PRD 编号）与专项（性能 / 安全 / 兼容）。

**不测什么**：明确排除项及理由，避免验收时扯皮。

## 2. 测试策略（分层）

| 层级 | 内容 | 执行方 | 通过标准 |
|------|------|--------|---------|
| 冒烟 | 主链路可用性 | 开发提测前自测 + 测试确认 | 冒烟用例 100% 通过 |
| 功能 / 集成 | PRD 功能与模块间交互 | 测试 | P0/P1 清零 |
| 系统 | 全量回归 | 测试 | 核心用例通过率 ≥ …% |
| 性能 | 并发 / 响应时间 | 测试 | 达到 PRD 第 4 节指标 |
| 安全 | 越权、注入、敏感信息 | 测试 | 无 P0/P1 安全漏洞 |
| UAT | 目标用户真实试用 | 业务方 / 种子用户 | 签字确认 |

## 3. 测试环境与数据

- 环境清单与版本要求；
- 测试账号准备（各角色各状态）；
- 测试数据来源；禁止使用未脱敏的生产数据。

## 4. 进入与退出标准

**进入标准（对应提测准入门）**：CI 全绿、冒烟通过、提测单附自测清单。

**退出标准（对应验收评审门）**：用例执行率 100%；P0/P1 清零；P2/P3 遗留经评审书面接受；性能与安全达标；UAT 签字。

## 5. 用例设计

- 设计方法：等价类划分、边界值、场景法、状态迁移；
- 用例组织：按 PRD 功能编号组织，编号规则 `TC-F功能编号-序号`（如 TC-FORUM-002-01）；
- 用例模板：

| 用例编号 | 前置条件 | 步骤 | 预期结果 | 优先级 | 结果 |
|---------|---------|------|---------|:------:|------|
| TC-FORUM-002-01 | 已登录用户 | 在技术问答版块发布含代码块的帖子 | 正文语法高亮渲染，版块列表可见 | P0 | 通过 |

> 异常流必须有覆盖：如未登录用户尝试发帖、机审拦截、网络中断时提交、重复提交等。

## 6. 缺陷管理

- 流转：新建 → 确认 → 修复 → 回归 → 关闭（工具：Jira / issue 列表）；
- 严重等级：按流程手册 4.3 节（P0–P3）；
- 缺陷日报：每日同步新增 / 修复 / 遗留。
