# 产品需求文档（PRD）模板

> **使用说明**：需求阶段（阶段二）使用。PRD 评审通过后即**基线化**（如 v1.0），后续修改走变更流程（见流程手册 4.2 节）。

| 文档信息 | 内容 |
|---------|------|
| 文档版本 | v0.1（草案；评审通过后改为 v1.0 基线） |
| 作者 | 产品负责人 |
| 评审状态 | 未评审 |
| 关联阶段 | 需求（阶段二） |
| 关联文档 | [BRD](../initiation/brd.md) |
| 最后更新 | YYYY-MM-DD |

## 1. 产品概述

- 背景与目标（一句话 + 链接 BRD）；
- 本期目标用户；
- 名词解释（产品内术语，如"版块""最佳答案"）。

## 2. 用户与场景

### 2.1 用户画像

> 从 BRD 细化，只保留与本期需求相关的画像。

### 2.2 用户故事

> 格式：作为【角色】，我想要【功能】，以便【价值】。每条故事必须有验收标准。

- 作为一名计算机专业大一学生，我想要在技术问答版块提问，以便 48 小时内得到可用的解答。

## 3. 功能需求

### 3.1 功能列表与优先级

> P0 = 本期必须有（MVP）；P1 = 重要但可延一个迭代；P2 = 锦上添花。

| 编号 | 功能 | 优先级 | 模块 |
|------|------|:------:|------|
| F-001 | … | P0 | … |

### 3.2 功能详情

> 每个功能写：描述、交互流程（或链接原型）、**验收标准**。

**F-001 【功能名】**

- 描述：……
- 流程：……（或链接原型页）
- 验收标准（Given / When / Then）：

```gherkin
Given 用户已注册并登录
When 在"技术问答"版块发布含代码块的帖子
Then 正文按语法高亮渲染，帖子出现在版块列表
```

## 4. 非功能需求

> 必须可测，写清指标值，否则测试无法验收。

| 类别 | 指标 | 要求 |
|------|------|------|
| 性能 | 接口 P95 响应时间 | ≤ … ms |
| 性能 | 版块列表首屏加载 | ≤ … s |
| 安全 | 内容审核 | 先审后发 / 即时审核 + 人工巡查 |
| 安全 | 个人信息 | 最小必要收集，清单见附录 |
| 兼容 | 目标端与版本范围 | … |

## 5. 信息结构与核心流程

- 页面 / 功能结构图（占位：链接或贴图）；
- 核心流程图（注册认证、发布、互动等主链路）。

## 6. 数据埋点需求

> 成功指标（BRD 第 7 节）靠埋点度量，这里逐条对应。

| 事件 | 触发时机 | 支撑指标 |
|------|---------|---------|
| register_success | 注册成功 | 注册渗透率 |
| … | … | … |

## 7. 发布计划

- 本期发布范围与不含项；
- 分批策略（如先认证用户内测）。

## 评审检查清单（需求评审门，四方会审用）

**产品**
- [ ] 每条功能有编号、优先级、验收标准；
- [ ] 非功能需求指标可测；
- [ ] 埋点覆盖 BRD 成功指标。

**开发**
- [ ] 每条需求技术上可行、工作量已初步评估；
- [ ] 无未决的技术依赖。

**测试**
- [ ] 验收标准可直接转写为测试用例；
- [ ] 异常流与边界场景已覆盖（或列入测试设计）。

**UI**
- [ ] 交互逻辑完整，无断链页面；
- [ ] 设计侧工作量已确认。
