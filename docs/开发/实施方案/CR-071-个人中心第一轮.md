## 1. 目标

把主 PRD §5.1「我的（帖子 / 收藏 / **设置** / **注销**）」那一格做成可用：用户能改掉默认昵称（G1）、能看到自己发过什么与被下架了什么（G2）、不新增任何越权面或字段外泄（G3）、无机审期间写入有限流 + 审计（G4）。**一轮含前端**（`frontend/` 限制已由发起人解除）。

## 2. 范围

**做**：`PUT /api/v1/users/me`（昵称 / 专业 / 签名）· `GET /api/v1/posts/mine` · `GET /api/v1/replies/mine` · `UserVo` 补 `status` · `ResultCode.PROFILE_UPDATE_TOO_FREQUENT(2008, 429)` · `V3` 两条复合索引 · `PROFILE_UPDATE` 审计 · 限流 10 次/小时 · 前端 `/settings` + `/me/posts` + `/me/replies` + 顶栏用户菜单入口。

**不做**（理由在需求文档 §2，此处只列实施侧边界）：`school` / `grade` 编辑（N9）· 头像上传（N3）· 通知偏好（N2）· 注销细则（归 F-ACC-003）· 已删内容回收站（N10）· **他人视角时间线**（三个新接口一律不接受身份参数，作者 id 只从令牌取）· **`@RequireRole` 声明与判定同源**（架构级，另开 CR）。

## 3. 三处评审查明的落码前修正（写死，不留给实现临场决定）

| # | 草案原写法 | 实测事实 | 本方案落法 |

**+45 例逐类归因**（`target/surefire-reports/` 逐文件相加，非估算）：新增类 **35** 例 = `ProfileApplicationServiceTest` 10 + `AccountProfileUpdateTest` 8 + `AccountRepositoryImplProfileUpdateTest` 5 + `UserControllerProfileTest` 4 + `PostRepositoryImplFindPageByAuthorTest` 3 + `ReplyRepositoryImplMyRepliesTest` 3 + `MyReplyControllerAuthTest` 2；改老类 **+10** 例 = `AccountCommandsValidationTest` 5→10、`ForumQueryApplicationServiceTest` 19→22、`PostControllerAuthTest` 7→9。**§6 原估 28~34 例偏低**：估算时未把"注册侧同批收紧"（④ 行）与 `FieldRules` 的 null/空串/归一三态各自展开，实际 45。

| # | 方案原写法 | 实际落法 | 为什么改 |
|---|---|---|---|
| ① | 端口 `int updateProfile(...)` | `void updateProfile(...)` | 返回值没有任何消费方：幂等由"差异集合为空"在用例层短路，行数只可能是并发下的 0/1，而两种情况对外行为一致。**不返回用不到的值** |
| ② | 「聚合内 trim + 校验」逐字段赋值 | **先全部校验、再统一赋值** | 逐字段赋值会让一次提交在"nickname 合法、bio 含 `<script>`"时停在改了一半的聚合上；`allOrNothing` 用例守这条 |
| ③ | 昵称空白判据写 `NON_BLANK_PATTERN` 注解 | 删该常量，交给聚合（`nickname="  "` → 聚合抛 1001） | 全空格能过 `@Size(min=2)`，但为它再叠一个 `@Pattern` 是把同一条规则拆两处；聚合这一份是必须的（无 setter 绕过），注解那份是冗余的 |
| ④ | 只给编辑侧加字符集禁则 | **注册侧 `RegisterCommand.nickname` 同批加上** | 实测缺口：编辑拒 `<`、注册不拒，则注册 `<script>` 昵称仍能进库——"唯一防线"漏一半。⚠️ 这**改变了既有对外行为**（注册含尖括号的昵称自本 CR 起 400/1001），属可见的行为收紧，已登记台账 |
| ⑤ | `MyReplyRow` 的 SQL 断言方式未定 | 直接**读 `@Select` 注解文本**断言 WHERE 片段 | 条件写在注解里而非 wrapper，Mockito 捕获不到；不这样断言，"顺手删掉父帖条件"不会让任何测试变红（反证④ 已实测：删两条 `p.` 条件 → 该用例红） |
| ⑥ | **推翻 ③ 行**：`NON_BLANK_PATTERN` 常量恢复，`nickname` 注解与聚合同时要 | 编辑侧 `nickname` 同时挂 `@Pattern(TEXT_ALLOWED_PATTERN)` + `@Pattern(NON_BLANK_PATTERN)`，聚合 `requireNickname` 保留 | 真机取证推翻了自己上一轮的理由：`nickname="    "`（4 空格）实测能过 `@Size(min=2)`、穿到聚合后返回的是**笼统的 `参数错误（1001）`**，用户看不出是"空白"这一条；`@NotBlank` 不适用（编辑侧 null 合法 = 不改）。⚠️ **代价是这条规则现存两处**（注解产具体文案、聚合防无 setter 绕过），与 ③ 行"不拆两处"的初衷相反——权衡后取"文案可诊断性"，两份各司其职、常量仍单点 |
| ⑦ | 契约快照未预料到注解可见性问题 | **springdoc 对可重复注解一个都不输出**：`nickname` 的两个 `@Pattern` 在 `UpdateProfileCommand` 里**全部消失**（只剩 `min/max`），而单 `@Pattern` 的 `major` / `bio` 正常输出 | 不是配置能修的（属 springdoc 读取实现）。已登记为[契约 README](../../设计/接口契约/README.md) §6.3 新增表达极限行，**判据唯一事实源指向 `FieldRules` 代码**；连带后果：`NON_BLANK_PATTERN` 这条规则**契约上看不见**，只有单测与真机 400 能证明它在 |
| ⑧ | 新端点 `@ErrorCodes` 按"业务错误码逐个列全"落 | 删去显式 `INVALID_PARAM`（**一次返工**） | 首次抓取实测 `400` 的 description 是 `参数错误（1001）；参数错误（1001）`——通用 400 本就由 `OpenApiErrorResponseCustomizer` 自动补，**这正是 §3 末段点名的 CR-049 v1.8 教训重犯**，且它同时是 ⑥ 行"看不到具体文案"的另一半原因。删声明 → 重建实例 → 重抓，才只剩一条 |
