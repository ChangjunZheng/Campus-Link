## 1. 目标

参照 CSDN / 掘金核心阅读体验与社区功能，补齐 Campus-Link 四项交互缺失，闭合"阅读 → 互动 → 发现用户 → 关注"社区环路：

1. **代码块复制 + 帖子目录大纲**——渲染能力已具备（highlight.js 29 语言、服务端 Markdown 净化），但交互层为零；
2. **草稿箱（localStorage）**——发帖误关即丢内容，学生用户移动端切换频繁；
3. **通知单条已读**——当前只有"全部已读"，单条点击后仍显示未读，削弱角标信任；
4. **他人主页 /u/:id**——关注 Feed 已落地（CR-074），但他人主页仍是 `Placeholder.vue`，社区闭环断裂。

### 对标分析

| 功能 | CSDN | 掘金 | Campus-Link 现状 |
|------|------|------|-----------------|
| 代码块复制 | 右上角复制按钮 | 复制按钮 | 无 |
| 目录大纲 | 右侧 H1~H3 大纲 | 目录侧栏 | 无 |
| 草稿箱 | 自动保存+手动 | 草稿箱 | 无（误关即丢） |
| 通知已读 | 点击即已读 | 点击即已读 | 仅全部已读 |
| 他人主页 | 完整个人主页 | 用户主页+动态 | Placeholder.vue |

## 2. 范围（做与不做）

**做**

- **功能 A**：代码块复制按钮 + 帖子目录大纲（纯前端，零后端零契约零迁移）
- **功能 B**：草稿箱 localStorage 版（纯前端，零后端零契约零迁移）
- **功能 C**：通知单条已读（后端 +1 受保护端点 + 前端乐观更新）
- **功能 D**：他人主页 `/u/:id`（后端 +2 公开端点 + 前端新页面 + 作者跳转）

**不做（明确排除，防止边界漂移）**

- 服务端草稿同步（需新表 + 新端点，排下一轮）
- 移动端目录抽屉（本期仅桌面侧栏）
- 代码块行号
- 获赞数 / 被采纳数聚合展示（需新 SQL，排下一轮）
- 头像上传
- 「届」徽章渲染
- 关注产生通知（CR-074 先例，避免新增通知 type + 前端文案链）

## 3. 改动点（文件级）

### 功能 A：代码块复制按钮 + 帖子目录大纲

纯前端，零后端零契约零迁移。

| 文件 | 动作 | 说明 |
|------|------|------|
| `frontend/src/views/PostDetailView.vue` | 改 | 渲染后遍历 `.post-content pre`，注入绝对定位复制按钮（Clipboard API + "已复制"反馈 2s）；布局改 flex（左主内容 + 右 w-56 sticky 目录），移动端隐藏目录 |
| `frontend/src/components/TableOfContents.vue` | 新增 | DOMParser 解析渲染后 HTML 中 H1~H3 标题，IntersectionObserver 高亮当前章节，点击平滑滚动；为无 id 的标题元素前端补加 `id`（`heading-${index}` 格式） |

**复制按钮实现细节**：
- 使用 `navigator.clipboard.writeText()`，降级判断：非 HTTPS 且非 localhost 时隐藏按钮
- 按钮样式：绝对定位 `pre` 右上角，hover 显示，点击后文案变"已复制" + checkmark 图标，2s 后恢复
- 每个 `<pre>` 包裹一个 `position: relative` 的容器 div（或直接给 pre 加 relative）

**目录大纲实现细节**：
- 从 `.post-content` 的 innerHTML 用 DOMParser 提取 h1/h2/h3
- IntersectionObserver `rootMargin: '-80px 0px -80% 0px'` 监听标题可见性
- 层级缩进：h1 → 0px，h2 → 12px，h3 → 24px
- 无标题时组件不渲染（纯文本帖无目录属正常行为）

### 功能 B：草稿箱 localStorage 版

纯前端，零后端零契约零迁移。

| 文件 | 动作 | 说明 |
|------|------|------|
| `frontend/src/composables/useDraft.ts` | 新增 | 草稿读写逻辑：saveDraft / loadDraft / clearDraft / listDrafts |
| `frontend/src/views/PublishView.vue` | 改 | 集成草稿：watch form 防抖 2s 自动保存、onMounted 恢复、发布成功清除 |

**存储策略**：
- key：`cl_draft`
- 结构：JSON 数组，每项 `{ boardCode, title, contentMd, savedAt }`
- 上限：最多 10 篇，按 `boardCode` 唯一（同版块新草稿覆盖旧草稿），超限淘汰 `savedAt` 最旧项
- `QuotaExceededError` 静默处理（catch 后 console.warn，不打断用户）

**恢复提示条**：
- 页面加载时若存在该版块草稿，显示提示条：「已恢复上次未发布的草稿（保存于 xx 分钟前）」
- 右侧"丢弃"按钮清除当前草稿
- 时间显示：相对时间（刚刚 / x 分钟前 / x 小时前 / x 天前）

### 功能 C：通知单条已读

后端 + 前端。

| 文件 | 动作 | 说明 |
|------|------|------|
| `backend/src/.../module/notification/web/NotificationController.java` | 改 | 新增 `POST /api/v1/notifications/{id}/read`，受保护，幂等 |
| `backend/src/.../module/notification/application/NotificationApplicationService.java` | 改 | 新增 `markAsRead(notificationId, userId)` 方法 |
| `frontend/src/api/notifications.ts` | 改 | 新增 `markNotificationRead(id: number)` |
| `frontend/src/views/NotificationsView.vue` | 改 | 列表项点击时 fire-and-forget 调用 + 乐观更新 UI + 刷新角标 |

**后端逻辑**：
- 校验 `notification.recipientId == currentUserId`，不匹配返回 404（不泄露他人通知存在性）
- 已读幂等：`is_read = true` 时直接返回 200，不重复 UPDATE
- 审计：首次标记已读无需审计（非安全敏感操作，与"全部已读"口径一致）

**前端逻辑**：
- 点击通知项 → 立即将该条 UI 标为已读（乐观更新）→ fire-and-forget 调用 `markNotificationRead`
- 失败时不回滚 UI（下次刷新自然恢复真实状态）
- 成功后刷新角标计数（调用已有的未读数 API）

### 功能 D：他人主页 /u/:id

后端 + 前端。

| 文件 | 动作 | 说明 |
|------|------|------|
| `backend/src/.../module/account/web/UserProfileController.java` | 新增 | `GET /api/v1/users/{id}` 公开端点，返回 UserProfileVo |
| `backend/src/.../module/account/application/UserProfileApplicationService.java` | 新增 | 聚合查询用户信息 + 统计数 |
| `backend/src/.../module/account/web/vo/UserProfileVo.java` | 新增 | id / nickname / major / bio / createdAt / postCount / followerCount / followingCount |
| `backend/src/.../module/forum/web/ForumController.java` | 改 | 新增 `GET /api/v1/users/{id}/posts` 公开端点，复用 forum application 层分页（G4 合规：forum web 编排 forum application） |
| `frontend/src/views/ProfileView.vue` | 新增 | 用户信息卡 + 帖子时间线 + 关注按钮（复用 `api/follow.ts`） |
| `frontend/src/router/index.ts` | 改 | `/u/:id` 路由从 Placeholder 改为 ProfileView |
| `frontend/src/views/PostDetailView.vue` | 改 | 作者昵称改为 `<router-link :to="/u/${post.authorId}">` |
| `docs/设计/接口契约/openapi.json` | 重生成 | 契约快照 v1.15 |

**UserProfileVo 字段**：
```json
{
  "id": 1,
  "nickname": "张三",
  "major": "计算机科学与技术",
  "bio": "热爱编程",
  "createdAt": "2026-03-01T00:00:00Z",
  "postCount": 12,
  "followerCount": 5,
  "followingCount": 3
}
```

**用户帖子列表**：
- 复用 `PostSummaryVo`（已有 viewCount / coverUrl）
- 分页参数：`page` / `size`（与首页帖子列表口径一致）
- 仅返回 `status = PUBLISHED` 且 `is_deleted = 0` 的帖子（他人视角，与"我的帖子"口径相反）
- 路由挂在 forum web 层（`GET /api/v1/users/{id}/posts`），因数据源是 forum 上下文的帖子表

**关注按钮**：
- 未登录 → 点击跳登录页
- 已登录且非自己 → 显示「关注 / 已关注」（复用 `api/follow.ts` 的 follow / unfollow / followState）
- 已登录且是自己 → 不显示关注按钮，显示「编辑资料」跳转 `/settings`

**架构合规**：
- `GET /users/{id}` 归 account web → account application（查用户 + 聚合关注数）
- `GET /users/{id}/posts` 归 forum web → forum application（查帖子分页）+ account application（仅读用户是否存在，由 forum web 编排）
- 帖子计数 `postCount` 在 account application 中通过 forum 端口读取（或直接 SQL COUNT），需确认依赖方向合规——若违反 G4 则改为 account web 编排两个 application 的返回值拼装

## 6. 回滚

- **功能 A + B**：纯前端，revert 对应 commit 即可；草稿数据在用户 localStorage，回滚后残留数据无害（key `cl_draft` 无其他消费方）
- **功能 C**：后端新端点无调用方即无副作用；前端 revert 后通知行为回到"仅全部已读"
- **功能 D**：后端两个公开 GET 端点无副作用（只读）；前端 revert 后 `/u/:id` 回到 Placeholder；**无迁移、无新表**，回滚无需数据修复
- **契约**：回滚后重生成 openapi.json 回到 v1.14

## 7. 风险与边界

| # | 风险 | 处置 |
|---|------|------|
| R1 | 代码块复制依赖 Clipboard API（HTTPS 或 localhost），HTTP 环境不可用 | 检测 `navigator.clipboard` 是否存在，不存在时隐藏复制按钮（优雅降级） |
| R2 | 草稿箱纯 localStorage，不跨设备、不跨浏览器，清缓存即丢 | 文档与 UI 均不承诺跨设备；服务端草稿同步排下一轮 |
| R3 | 目录大纲依赖服务端渲染 HTML 中有 h1~h3 标签 | 纯文本帖无目录属正常行为，组件不渲染 |
| R4 | 他人主页 postCount / followerCount 为实时聚合查询 | 单校规模（<5000 用户）无性能压力；若后续需要可加 Redis 缓存 |
| R5 | 通知单条已读为乐观更新，网络失败时前端已标已读但服务端未同步 | 下次刷新自然恢复真实状态；不做回滚（体验优先于一致性） |
| R6 | 功能 D 依赖功能 A 完成 PostDetailView 改造 | 实施顺序已保证 A 先于 D；若 A 延期则 D 的作者跳转可独立拆出 |
