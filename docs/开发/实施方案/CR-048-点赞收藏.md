# CR-048 实施方案：F-FORUM-005 点赞收藏

> 登记于 [变更台账](../../变更日志/变更台账.md) §1（实施前）。**本方案待发起人确认，确认前不动代码。**

## 1. 目标

落实 PRD [F-FORUM-005](../../需求/产品需求文档.md) 验收标准：Given 已登录用户，When 对帖子或回复点赞，Then 计数 +1 且再次点击取消（去重）；收藏的帖子可在"我的收藏"查看。为 Sprint 3 的"互动"类功能（通知 / 热榜）打基础。

## 2. 范围

**做**：
1. **点赞（toggle）**：帖子、楼层回复各一个端点，未赞 → 插入 + 计数 +1；已赞 → 删除 + 计数 -1（去重靠 `likes` 表主键 `(user_id, target_type, target_id)`）；
2. **收藏（toggle）**：帖子收藏 / 取消，语义同上（`favorites` 主键 `(user_id, post_id)`）；
3. **我的收藏**：按收藏时间倒序分页列出自己收藏的帖子摘要；
4. **登录态回显**：帖子详情出参补 `likedByMe` / `favoritedByMe`、每个楼层补 `likedByMe`（仅登录时填充，**详情端点保持公开**，匿名访问不出这些字段）；
5. 前端：详情页帖子点赞 / 收藏按钮 + 楼层点赞；新增"我的收藏"页 `/favorites` + 顶栏入口（需登录）；
6. 单测（含每个新端点「匿名 → 401」）+ 契约快照再生成（v1.7）。

**不做**（如实列出）：
- 通知发放（"有人赞了你 / 收藏了你"）——属 F-SOC-001，验收该项挂起；
- 个人主页整体落地——`/u/:id` 仍为占位页，"我的收藏"本期落独立页，主页落地时再挂入；
- 禁止点赞 / 收藏自己的内容——PRD 无此要求，不做限制；
- 回复的收藏——`favorites` 表只有 `post_id`，PRD 只要求收藏帖子；
- 热榜联动（`hot_score` 属 ADR-006 定时任务）。

**零迁移**：V1 的 `likes` / `favorites` 表与 `posts.like_count` / `posts.favorite_count` / `replies.like_count` 均已就位。

## 3. 改动点（文件级）

**backend（`module/forum` 照抄既有四层范式）**：
- `domain/gateway/`：新增 `LikeRepository`、`FavoriteRepository` 端口；
- `application/`：新增 `InteractionApplicationService`（toggle 帖子赞 / 楼层赞 / 收藏 + 我的收藏查询），`cmd/ForumResults` 增 `InteractionResult(boolean active, int count)`；
- `infrastructure/persistence/`：`LikeRepositoryImpl` / `FavoriteRepositoryImpl` + `mapper/LikeMapper` / `mapper/FavoriteMapper`（**必须在 `..mapper..` 包**，守护测试强制）；
- `web/`：`PostController` +2（`POST /{id}/like`、`POST /{id}/favorite`）、`ReplyController` +1（`POST /{id}/like`）、新增 `FavoriteController`（`GET /api/v1/favorites/mine`）；4 个端点全部 `@SecurityRequirement` + `CurrentUser.requireId`；
- 详情出参：`PostDetailVo` + `likedByMe` / `favoritedByMe`、`ReplyVo` + `likedByMe`；`ForumQueryApplicationService.postDetail` 增可空 userId 分支；
- `ResultCode` **无新增**（目标不存在复用 3001 NOT_FOUND）。

**frontend**：`src/api/forum.ts` +4 方法与类型；`PostDetailView.vue` 加点赞 / 收藏交互；新增 `views/MyFavoritesView.vue` + `router/index.ts` 路由 + 顶栏入口。

**docs**：`openapi.json` 再生成、[技术方案](../../设计/技术方案.md) §5 +4 行、api/README v1.7、台账回置、驾驶舱、本方案文末实施结果。

## 4. 步骤

1. 后端四层 + 4 端点：toggle 在同一事务内"先试插入，主键冲突则删除"，计数随行内 `setSql` 增减（与 reply_count 同法）；双击竞态由主键唯一约束兜底（冲突即走取消分支），不会重复计数；
2. 详情出参扩展 + 单测（toggle 去重 / 取消 / 计数回退、详情匿名不出 `likedByMe`、3 个新写端点匿名 → 401）→ `mvn verify` 全绿（基线 125）；
3. 前端两页 + 交互；
4. 真机浏览器冒烟 + 契约快照再生成；
5. 文档同步 + 收尾。

## 6. 回滚

## 实施结果

**实施日期**：2026-09-13。**凭证**：commit message CR-048（待提交）。

**按计划落地**：四端点（toggle ×3 + `/favorites/mine`）、`InteractionApplicationService`、`LikeRepository` / `FavoriteRepository` 及实现与 Mapper、详情 / 楼层出参登录态回显（匿名恒 false）、`MyFavoritesView` + `/favorites` 路由（requiresAuth）+ 顶栏下拉入口、契约快照再生成。

**偏差（均为小幅）**：
1. **楼层出参加 `likeCount`**：原方案楼层只加 `likedByMe`；PRD"计数 +1"需可见反馈，故楼层项同步带计数——链路上 `Reply` 聚合 + `likeCount` 字段（`rehydrate` 传入、`post()` 恒 0）、`ReplyConverter` 读回 `replies.like_count`（原注释"like_count 不属本 Sprint 模型"随之失效并改写）、`ReplyItem` / `ReplyVo` + 字段。测试中 5 处 `Reply.rehydrate` 字面量同步加参。
2. **`InteractionResult` 字段名为 `active`**（方案行文曾写 liked / favorited 意象），取 toggle 语义，帖子 / 楼层 / 收藏三端点共用；
3. **计数为 toggle 后读回**（`selectById` 回读），而非"base ± 1"推算，避免并发下回显漂移；
4. 匿名详情**仍返回** `likedByMe` / `favoritedByMe` 字段但值恒 false（方案写"不出这些字段"——布尔字段统一恒 false 更利于前端判空，口径未变）。

**验证**：`mvn verify` 全绿 **138** 个（基线 125 → +13：`InteractionApplicationServiceTest` 6 + `InteractionControllerAuthTest` 7）；真机（后端 8094 + 前端 5199 临时栈）：匿名四端点均 401 / 4001，登录后帖子点赞 0→1→0 toggle、收藏 / 取消、楼层点赞 toggle、`/favorites` 列表回显、匿名详情回显恒 false、不存在楼层 3001，契约 `git diff` 仅 +4 端点与 2 个出参 schema 扩展，无意外漂移。冒烟环境 CORS 白名单需含 5199（临时栈参数，不影响 5173 默认）。
