## 1. 目标

在不推翻 [CR-023](../../变更日志/变更台账.md#cr-023) / [CR-024](../../变更日志/变更台账.md#cr-024) / [CR-025](../../变更日志/变更台账.md#cr-025) 沉淀的令牌体系前提下，按发起人选定的**方案二「适度品牌化」**提升 9 个页面的视觉层次与精致度：首页有品牌氛围、版块可一眼区分、列表结构统一、详情楼层有重点、登录页有品牌感、全局有连贯的交互反馈。**纯展示层：不改任何接口 / 路由 / 数据流 / 后端 / 依赖。**

## 2. 范围

- **做**（六组，分 5 批落地，每批停下汇报）：
  - **A 全局质感**：顶栏 sticky + 滚动后毛玻璃底；路由切换淡入；交互过渡时长令牌；`:focus-visible` 键盘焦点环；细滚动条；主区间距与页脚细化；
  - **B 首页**：hero 重排为品牌横幅（左 slogan/按钮，右「快速开始」面板）；6 版块卡配线性图标 + 识别色淡底图标容器 + hover 微抬；
  - **C 列表统一**：新增 `components/PostListItem.vue`，首页 / 版块 / 搜索 / 收藏四处列表改用它（**闭环 [界面规范](../../设计/UI规范/界面规范.md) §5.1 挂账的 P0**），首页补摘要、行 hover 底色、回复数轻量徽章；
  - **D 详情页**：最佳答案楼层整体浅绿底 + 左侧竖条强调；楼层号徽标；`authorId` 比对显示「楼主」（复用 [CR-043](../../变更日志/变更台账.md#cr-043) 已透出字段，零接口改动）；
  - **E 登录页**：桌面双栏（左品牌区：logo / slogan / 三条价值主张；右现有表单卡），窄屏折叠为顶部品牌条，`meta.bare` 与两步注册流程不变；
  - **F 发帖页**：Markdown 工具条由裸文字（B/I）改线性图标按钮。
- **不做**：
  - 不加任何 npm 依赖（**`highlight.js` 代码高亮是 ADR-005 功能欠账，不混入本 CR**，要做另开）；不换组件库、不引图表 / 动效库；
  - 不改令牌既有取值（主色 / 链接色 / 字号 / 间距 / 圆角**只新增不修改**）；字重仍只用 400 / 500；圆角不加大；无插画、无位图、无卡片投影（浮层阴影维持现状）；
  - 不改后端、不重生成 OpenAPI 快照（`git diff openapi.json` 应为空）；不改四态（骨架 / 空 / 错 / 3001）、分页口径、路由守卫、`?floor=` 定位等既有交互逻辑；
  - 不做深色模式开关、不做左侧栏、不做通知页句式重构（通知列表仅做行 hover 等通用润色）。
- **对 [界面规范](../../设计/UI规范/界面规范.md) §2「装饰为零」的定点偏离（仅 4 处、可枚举，随本 CR 在该规范加注，非推翻）**：
  1. hero **全站唯一**一处极淡主色渐变底（主色 8% → 透明）；2. 6 版块各一低饱和识别色，**仅**用于图标容器底 / 小点缀，不做文字色（守 AA）；3. 版块卡 hover 允许 `translateY(-2px)`，反馈仍靠主色描边 + 底色、**不用投影**；4. 毛玻璃 `backdrop-filter` **仅** sticky 顶栏一处。

**与原计划的偏差（2 处自修复，均不改变范围与对外契约）**：

1. **PostListItem 交互模式**：原拟「整行 `li` + JS 点击跳转 + `role=link`」，真机发现该模式丢失真实 `href`（无法中键新开标签 / 右键复制链接 / 键盘原生聚焦），改为**标题是真实 `RouterLink`（`/post/:id`）、整行只做 hover 通栏底色**——可访问性与原生行为更稳，视觉效果不变；
2. **路由淡入的根节点**：`<transition>` 直接包多根 fragment 视图（Board / Search / Notifications / Favorites 是多根模板）时 Vue 报 "non-element root node that cannot be animated" 且淡入失效，在 `App.vue` 的 transition 内包一层 `<div :key="fullPath">` 单根元素修复，修复后控制台该告警归零。

**验证限制（如实声明，需发起人宽屏复核）**：

- 走查浏览器视口固定 **655px 宽**（CDP 改视口报 "Session with given id not found"，无法切尺寸），故**桌面 ≥768 的 hero 左右横排、登录品牌双栏、版块 md 三列未经目视**，由 `npm run build` 通过 + 标准 Tailwind 响应式类（`md:flex-row` / `md:w-[264px]` / `el-col md=8`）兜底；窄屏 655 宽度下无横向溢出、折叠正确；
