## 1. 目标

参照 CSDN / 掘金，补齐三类内容发现与展示能力：**帖子阅读数**、**列表封面图**、**关注用户与「关注」Feed**（PRD F-SOC-002 由 P1 提前实施，属范围决策、待发起人确认本方案即视为确认该项）。

## 2. 范围（做与不做）

**做**
- **阅读数**：`V4` 迁移加 `posts.view_count INT NOT NULL DEFAULT 0`；计数在帖子详情读取时去重触发——登录按用户、匿名按 IP，**每帖每账号每日至多 +1**（Redis `SETNX` 当日过期）；计数失败不影响详情返回（吞错，但**须记 1 行 WARN**——按日志分档不打全栈，避免静默失败不可见）。列表与详情 VO 下发 `viewCount`。
- **封面图（外链方案，零存储依赖）**：`V4` 加 `posts.cover_url VARCHAR(512) NULL`；**发帖时**服务端从 `contentMd` 提取首张 `https` 图片 URL 落库（一次提取、读时零成本）；列表 / 详情 VO 下发 `coverUrl`；前端列表项右侧 96×64 缩略图（无图不占位）。**不做上传**——真上传依赖对象存储选型（发起人须开账户），仍按技术方案 P1 另立 CR；旧帖不回填封面（新帖生效）。
- **关注 Feed**：`V4` 新增 `follows` 表（`follower_id` + `followee_id` 联合主键、`idx_followee`）；归 **account 上下文**（用户关系域）——端口 `FollowRepository` 在 domain、应用服务提供 follow / unfollow / follow-state（`{following, followerCount, followeeCount}`）；forum 侧 `pageByAuthors(authorIds)` 时间序分页，首页「关注」Feed 由 forum web 编排两上下文 application（依赖方向合规）。前端：**排序切换组新增「关注」项**——现状是 `el-radio-group`「最新 / 热门」（评审指出"第三 Tab"表述与现状不符，落实为该组第三项），仅登录渲染、空态引导去关注；详情页作者行「＋关注 / 已关注」小按钮（未登录跳登录）。

**不做（如实登记）**
- 图片上传 / 对象存储（另立 CR）；阅读数进热榜公式（**ADR-006 口径不动**，互动分不含阅读，试点后再评估）；关注产生通知（避免新增通知 type + 前端文案链，CR-066 先例）；粉丝 / 关注清单页；旧帖封面回填；详情页作者卡片（B 档后续）。

## 3. 改动点（文件级）

- **backend**：`db/migration/V4__post_views_and_follows.sql`（新）；forum：Post 聚合 + viewCount/coverUrl、`PostRepository#incrementViewCount`、发帖用例提取封面、`ForumQueryApplicationService#pageByAuthors`、VO 两字段；account：`FollowRepository` 端口 + 适配器、`FollowApplicationService`、`FollowController`（POST/DELETE `/users/{id}/follow`、GET `/users/{id}/follow-state`）；新错误码 `2009 CANNOT_FOLLOW_SELF(400)`；复用 `2007 / 4001 / 4002`；**阅读数去重键一律走 `RedisKeys.of(...)` 前缀**（约定强制，`RedisKeyNamespaceTest` 有适配器断言）。
- **契约**：`PostSummaryVo` / `PostDetailVo` 加 `viewCount` / `coverUrl`；新增 3 个端点（follow 两支受保护、follow-state 需登录）；**openapi 快照再生成 v1.14 + 逐行归因**（本 CR 必经步骤）。
- **frontend**：`HomeView`（排序组加「关注」项 + 空态）、`PostListItem`（封面缩略图 + 阅读数）、`PostDetailView`（阅读数展示 + 作者行关注按钮）、`api/forum.ts` 增量 + **新建 `api/follow.ts`**（follow 三接口；评审核实 `api/` 下现无 account.ts，按职责独立命名）。

## 8. 实施结果（实施完成后追加）
