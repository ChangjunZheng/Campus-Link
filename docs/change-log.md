## 0. 台账使用说明

手册 4.2 节规定基线后的变更必须走：**提交变更申请 → 评估影响（范围 / 排期 / 质量）→ 变更评审 → 更新基线并同步产品 / 开发 / 测试 / UI 四方**。

本台账是该流程的登记载体。条目分两类：

- **CR-001 ~ CR-008：事后补录**。这 8 次变更发生时**均未走 4.2 流程**，本台账据各文档内嵌"变更记录"补录，目的是使已发生的变更可追溯，**不主张当时执行了变更评审**；
- **CR-009 起：正常登记**。此后新增变更应在实施前登记，并在 commit message 中写入 CR 编号（版本控制已由 [CR-011](#cr-011) 恢复，该要求自此可执行）。**已知例外**：CR-010 为结构变更已落地后才补登记；CR-012 / CR-013 / CR-014 为发起人当面指令、实施前登记，CR-015 为实施后、提交前补登记，均未经正式变更评审。

> **证据等级声明**：仓库已于 2026-09-11 合并为根目录单一 monorepo（[CR-010](#cr-010)）并配置远程 `https://github.com/Epoch-1483/Campus-Link`、推送首次提交 `837a22f`（[CR-011](#cr-011)），版本控制缺口就此关闭。但**首次提交晚于本台账全部条目所记录的日期**——它是一次性把既有成果入库，并不含 CR-001 ~ CR-015 各自的提交。因此这 15 条的日期仍**全部取自文档自述的变更记录**，无法用提交历史交叉验证；**自 CR-011 之后的变更在提交后即具备 git 凭证**。
