## 0. 台账使用说明

手册 4.2 节规定基线后的变更必须走：**提交变更申请 → 评估影响（范围 / 排期 / 质量）→ 变更评审 → 更新基线并同步产品 / 开发 / 测试 / UI 四方**。

本台账是该流程的登记载体。条目分两类：

- **CR-001 ~ CR-008：事后补录**。这 8 次变更发生时**均未走 4.2 流程**，本台账据各文档内嵌"变更记录"补录，目的是使已发生的变更可追溯，**不主张当时执行了变更评审**；
- **CR-009 起：正常登记**。此后新增变更应在实施前登记，并在 commit message 中写入 CR 编号（版本控制已由 [CR-011](#cr-011) 恢复，该要求自此可执行）。**已知例外**：CR-010 为结构变更已落地后才补登记；CR-012 / CR-013 / CR-014 / CR-016 / CR-019 / CR-020 / CR-021 为发起人当面指令或决定、实施前登记，CR-015 / CR-017 / CR-018 为实施中/实施后登记，均未经正式变更评审。

> **证据等级声明**：仓库已于 2026-09-11 合并为根目录单一 monorepo（[CR-010](#cr-010)）并配置远程 `https://github.com/changjunzheng/Campus-Link`、推送首次提交 `837a22f`（[CR-011](#cr-011)），版本控制缺口就此关闭。但**首次提交晚于本台账全部条目所记录的日期**——它是一次性把既有成果入库，并不含 CR-001 ~ CR-021 各自的提交。因此这 21 条的日期仍**全部取自文档自述的变更记录**，无法用提交历史交叉验证；**自 CR-011 之后的变更在提交后即具备 git 凭证**：CR-012 / CR-013 / CR-014 → `a0eeb11`，CR-015 → `a456b8b`，CR-016 → `68d40ae`，CR-017 / CR-018 / CR-019 → `f19fc79`（**三个 CR 合并为一次提交**，提交正文按 CR 分段写明各自内容，已推送 `origin/main`；合并原因是三者修改同一批文档、按 CR 拆分须逐块挑选，风险高于收益）。**CR-020 / CR-021 → `63ed21c`**（**两个 CR 合并为一次提交**，正文按 CR 分段写明各自内容；合并原因同 `f19fc79`——二者修改同一批文档，按 CR 拆分须逐块挑选，风险高于收益）。**一处未遵循**：CR-016 的提交 `68d40ae` 正文未写入 CR 编号（`a0eeb11`、`a456b8b` 与 `f19fc79` 均已写），台账与 git 的双向对齐在该条上只能靠日期与内容推断。<br>**CR-022 起（2026-09-12）**：本条登记时**尚未提交**，提交后此处补齐凭证；即 CR-022 在登记时不具备 git 凭证（与 CR-020 / CR-021 登记时的情形相同），**该状态在提交后即结束**。
