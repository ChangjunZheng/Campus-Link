## 1. 问题陈述与目标

### 1.1 问题陈述

两个小问题，都不致命，但都在消耗内容消费效率：

1. **长帖消费成本高**：F-FORUM-002 允许正文 ≤ 20000 字，列表卡片只能截断正文前若干字——长帖（面经、教程、踩坑总结）的截断开头往往不是重点（常见"楼主大三，最近在准备…"式的铺垫），用户只能点进去才知道值不值得读；
2. **标签覆盖率不稳定**：标签完全依赖用户自觉（0~5 个自选），不打的帖子在版块聚合与检索（F-FORUM-008）里就丢了入口。

AI 摘要与推荐标签恰好都是**生成一次、处处复用**的低成本增强。但要如实说：**这不是痛点级需求**——没有它社区照样转；它的价值是"让内容消费顺一点"，所以它只配"顺手做"的投入档位。

### 1.2 目标

| # | 目标 | 度量方式（见第 6 节） |
|---|------|-------------------|
| G1 | 长帖在列表页可被快速判断"值不值得点" | 正文 ≥ 500 字的帖子摘要生成覆盖率 ≥ 95%（其余为生成失败降级，正常回退截断） |
| G2 | 标签覆盖质量提升 | 推荐标签采纳率 ≥ 40%（展示推荐的用户中点选 ≥ 1 个的比例） |
| G3 | 零主链路影响 | 摘要 / 标签服务任何故障下，发帖与列表加载行为与无此功能时一致 |

## 2. 非目标（Non-goals）

| # | 不做什么 | 为什么 |
|---|---------|--------|
| N1 | **不回刷全量历史帖** | 只对发布后增量内容异步生成；历史帖量大、价值低，回刷是纯成本。确有个别需要，留手动触发口（管理员侧，P2） |
| N2 | **不自动修改已发布帖子的标签** | AI 只在**发帖编辑器内**给"推荐标签"供用户点选，发布后永不擅动用户内容——用户对内容元数据的最终控制权不可让渡 |
| N3 | **不做内容质量评分 / 情感分析 / 水贴识别** | 归内容治理（F-SAFE 系列与云机审），且评分体系会引发争议，不是本期该碰的 |
| N4 | **不做标题改写 / 封面图生成** | 标题是作者表达，AI 改写必然越权；封面图是另一条产品线 |
| N5 | **摘要不在详情页展示** | 详情页有全文，摘要在详情页是重复信息；摘要只服务列表页的"点不点"决策 |
| N6 | **不做短帖摘要** | 正文 < 500 字的帖子，AI 摘要相对"截断"没有信息增量，纯烧钱 |

## 3. 用户与场景

### 3.1 用户故事

- 作为一名**浏览面经的学生**，我想在列表卡片上直接看到"3 轮技术面 + 1 轮 HR，重点问了 Redis 持久化和线程池参数"这样的摘要，以便不点进去就知道这份面经覆盖什么；
- 作为一名**发帖的新手**，我打不出合适的标签，希望系统根据内容推荐几个现成标签供我点选，以便我的帖子能被检索到；
- 作为一名**熟练发帖者**，我希望 AI 永远不擅自给我已发布的帖子加东西，以便我对自己的内容有完全控制。

### 3.2 边界场景（必须覆盖）

- 摘要生成失败 / 超时 / 开关关闭 → 列表卡片**回退为现有正文截断**，无任何异常痕迹；
- 推荐标签生成失败 → 编辑器不显示推荐区块（不显示"生成失败"）；
- 用户打满 5 个标签 → 不再展示推荐区块；
- 用户点选推荐标签后自行删除 → 以用户最终提交为准；
- 机审拦截的帖子 → 不生成摘要（发布即审，未发布的帖子不进异步队列）；
- 帖子被编辑（F-FORUM-007 上线后）→ 异步重算摘要，期间列表显示旧摘要或回退截断。

## 4. 功能需求

### 4.1 功能列表与优先级

| 编号 | 功能 | 优先级 | 模块 |
|------|------|:------:|------|
| F-AI-002a | 长帖摘要（正文 ≥ 500 字，列表卡片展示） | **P0** | AI 辅助（`module/ai`） |
| F-AI-002b | 推荐标签（发帖编辑器内点选采纳） | **P0** | AI 辅助 |
| F-AI-002c | 埋点 | P0 | 数据 |

### 4.2 功能详情与验收标准

**F-AI-002a 长帖摘要（P0）**

- 描述：帖子发布成功后进入异步队列，仅当正文 ≥ 500 字时调用 LLM 生成 **1~2 句、≤ 60 字**的摘要，落库缓存（每帖一次，编辑重算）；列表卡片以摘要行替代现有正文截断行。
- 业务规则：只描述帖子内容，不评价（禁止"这篇帖子非常精彩"式空话，提示词约束）；摘要失败静默回退截断；成本护栏同 F-AI-001（仅增量、落库缓存、月成本上限可配置）。

```gherkin
Given 用户发布正文 ≥ 500 字的帖子且异步生成成功
When 其他用户浏览列表页
Then 该帖卡片显示 ≤ 60 字的摘要行，不含评价性措辞

Given 用户发布正文 < 500 字的帖子
When 列表页渲染
Then 不生成也不显示摘要，卡片与现有截断展示一致

Given 摘要服务不可用
When 用户发布长帖并浏览列表
Then 卡片回退正文截断，发帖流程与列表加载不受任何影响
```

**F-AI-002b 推荐标签（P0）**

- 描述：发帖编辑器内，当用户已输入标题（且正文 ≥ 50 字或停顿触发）时，展示"推荐标签"区（从**既有标签集合**中推荐 0~5 个），用户点选即加入自己的标签选择——**采纳与否完全由用户决定**，发布后 AI 不再触碰标签。
- 业务规则：推荐范围限于站内既有标签集合（防自由文本脏数据，与主 PRD F-FORUM-002 的标签口径一致）；用户已打满 5 个标签时不展示。

```gherkin
Given 用户在编辑器输入了标题与 ≥ 50 字正文且未打满 5 个标签
When 推荐生成完成
Then 编辑器显示 ≤ 5 个推荐标签，用户可点选加入、可忽略

Given 用户已发布帖子
When 任何后续流程运行
Then 已发布帖子的标签不被 AI 修改
```

**F-AI-002c 埋点（P0）**

| 事件 | 触发时机 | 关键属性 | 支撑指标 |
|------|---------|---------|---------|
| summary_shown | 列表卡片渲染 AI 摘要 | post_id、board_id | 摘要覆盖率（G1）、CTR 观察分母 |
| summary_click | 点击带摘要的卡片 | post_id | 带/不带摘要卡片 CTR 对比（观察项） |
| tag_suggest | 推荐标签展示 | 推荐数量 | 推荐渗透 |
| tag_adopt | 用户点选推荐标签 | 采纳数量 | 采纳率（G2） |

## 5. 技术约束与依赖

- `module/ai` 上下文由 F-AI-001 建立；**LLM 网关适配器若 F-AI-001b（语义版）未先行，则在本功能首次落地**（F-AI-001 检索版零 API 不需要网关）——网关端口定义在 domain、HTTP 适配器在 infrastructure，ArchUnit 自动覆盖；
- 摘要与 F-AI-001b 的标题 embedding **共享同一条异步生成管道**（同一队列、同一降级与成本护栏），避免两套异步设施；
- 摘要落库：`post` 表扩展或 `ai_summary` 表（设计阶段定，走 `V<n>__` 迁移）。

## 6. 成功指标

| 指标 | 定义 | 目标 | 评估时点 |
|------|------|------|---------|
| 摘要覆盖率 | 有摘要的 ≥500 字新帖 / 全部 ≥500 字新帖 | ≥ 95%（缺口 = 生成失败） | 上线 1 周 |
| 推荐标签采纳率 | tag_adopt 用户 / tag_suggest 用户 | ≥ 40% | 上线 2 周 |
| 带/不带摘要 CTR | 列表卡片点击率对比 | 观察项（不设硬目标——内测期样本小） | 内测期 |
| 月成本 | LLM API 花费 | ≤ 5 元 / 月 | 持续 |

## 7. 发布计划与开放问题

- **排期**：增量约 **0.5 天**，**必须搭 F-AI-001 的便车**（同一 CR 批次或紧随其后实施）；单独排期不值得；
- **前置**：F-AI-001 已登记实施（共享其 module/ai 与异步管道）。

| # | 开放问题 | 责任人 | 阻塞性 |
|---|---------|--------|--------|
| Q1 | 摘要字数上限 60 字与"仅长帖 500 字"阈值定稿 | 产品 + 开发 | 阻塞开发 |
| Q2 | 推荐标签触发时机（输入正文即推 vs 点击"推荐"按钮按需推——后者更省） | 开发 | 不阻塞 |
| Q3 | 编辑重算摘要的时效（异步延迟容忍窗口） | 开发 | 不阻塞 |
