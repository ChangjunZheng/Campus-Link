# 产品优化与新增业务需求建议（备料）

## 0. 结论先行

这个项目现在**最大的瓶颈不是功能数量，而是三件事**：

1. **真实名册（B1 / B2）没到位** ⇒ 没有真实用户（[下一步行动](../下一步行动.md) §1，唯一剩余外部依赖）；
2. **内容冷启动没有动作**——面经版块实测 1 篇 6 字、`tags` / `post_tags` 全库 0 行（[评审纪要](../评审/增量PRD评审纪要.md) §1 的实测证据）；
3. **安全运营的人工闭环没有打通**——内容处置只有 API（[CR-066](../变更日志/变更台账.md#cr-066)），没有举报入口与处置台 UI，`/admin` 仍是占位页（[问题清单](../项目现有问题清单.md) F-006 只到 🟡）。

在此状态下**继续堆功能收益递减**。以下建议围绕「为真实用户内测做准备」排序，而不是「把 PRD 填满」。

## 2. 新增业务需求建议（按「为内测铺路」排序）

### N1 「等你来答」模块 / 无最佳答案筛选 ★ 最值得先做

产品定位第一句就是「问有所答」，但冷启动期最缺的不是浏览（热榜已覆盖）而是**回答**。用现成的 `posts.is_accepted` / `accepted_reply_id` 列做「无采纳答案」筛选 + 首页一个「等你来答」入口，把产品的核心循环（提问 → 回答 → 采纳）真正转起来。比再做任何展示类功能都符合定位。

### N2 他人主页最小版（`/u/:id`，F-003 的另一半）

CR-074 一旦落地详情页关注按钮，「点作者进占位页」的矛盾会立刻变得刺眼。最小版只需：昵称 + bio + 该用户公开帖子时间线——复用 `GET /posts/mine` 的查询逻辑，参数从「本人」改为「authorId」，可见性口径（自删不出现、下架的按全站口径不出现）现成。这也是关注 Feed 的自然落点：**关注了人却没地方看人，功能就断了一半**。注意 [评审纪要](../评审/增量PRD评审纪要.md) §5 已锁的实施顺序（CR-067 → 036 → 042 抢 `users` 表）与本项无冲突——本项走 forum 侧新端点，不动 `PUT /users/me`。

### N3 举报入口 + 最小处置台 UI（F-SAFE-002 最小版）★ 内测前必须有

处置 API（[CR-066](../变更日志/变更台账.md#cr-066)）已经在了，缺的是整条人工链：帖子 / 楼层「举报」按钮 → 管理员能看到举报列表 → 一键调既有下架端点。**上真名册、放真实用户之前，这条人工闭环必须存在**——校园实名社区靠举报 + 人工处置完全可以支撑，这也是把 `/admin` 占位页变成真页面的最小版本。**它不需要等 A3-8 的第三方机审决策**（这是它与 F-005 的关键区别）。表结构上 `reports` 表 V1 已就位、同样零迁移起家。

### N4 本地敏感词表（机审的「校内降级版」）+ A3-8 决策建议

明确建议：**A3-8 建议按「本地词表 + 举报人工处置先行、第三方机审延后到有量级之后」拍板**。理由：学籍核验实名准入 + 单校封闭社区，内容风险模型和开放互联网完全不同，第三方机审按量计费在试点期是纯成本（[决策材料](../评审/部署与机审选型决策材料.md) 备料已齐、只差拍板）。这个决策同时解开三件事：BUG-006（发帖页「将进行机审」的虚假文案）、E-013 候选②、F-005 的最小闭环。⚠️ **前提**：这属于降级判断，须由发起人正式拍板并登记，不能静默放过；`reports` / 词表命中后的处置仍走审计留痕，生产红线「机审 fail-closed」在第三方机审引入前以「词表命中即拦截 + 人工复核」口径重述。

### N5 面经结构化发帖模板

[CR-038](../需求/产品需求文档-面经AI追问练习.md) 被否的三重前置里，「内容不足」和「机审未实现」都可以绕开：给 `interview` 版块做结构化模板（公司 / 岗位 / 轮次 / 问题清单），发帖时引导填写。不依赖 AI、不依赖机审决策，却直接改善「求职有路」支柱的内容质量，还为将来 CR-038 解禁时准备好结构化数据。

### N6 标签闭环（F-007）+ 固定种子标签集

[评审纪要](../评审/增量PRD评审纪要.md) §5 已指出这是 [CR-033](../需求/产品需求文档-发帖相似问题推荐.md)（相似问题推荐**纯检索版**）的唯一前置。补充一个冷启动要点：**不要做自由输入标签，先灌一组固定种子标签**（课程名、技术栈、竞赛名），否则会复现「tags 表 0 行、推荐无从谈起」的死结（F-007 / CR-037 被否的同一条证据）。自由标签可内测后再放开。

| X5 | **图片上传 / 对象存储** | CR-074 已正确推迟（封面走外链方案），维持 |

## 5. 节奏建议：把「内测就绪」当里程碑

Sprint 4 原计划是「治理与收尾」（机审 / 举报 / 后台 / 注销）。结合现状，建议把真正的下一个里程碑定义为：

**真实名册到位 → `bypass=false` 全链路回归（W-04 补偿③）→ 20~30 篇种子内容 → 小范围内测**

为此必须的最小清单：

1. **注销 F-002 最小版**（合规要求，PRD F-ACC-003 是 P0）——注意「冷静期可登录 vs `isActive()` 拦登录」的[口径冲突](../评审/增量PRD评审纪要.md)（§3 末段 / D-2）须先裁决；
2. **举报处置闭环**（= N3）；
3. **移动端走查**（= O3）。

其余功能（标签、主页、相似问题推荐纯检索版）都可排在内测之后、按真实使用数据定优先级。
