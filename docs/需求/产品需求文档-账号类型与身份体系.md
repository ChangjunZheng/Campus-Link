## 1. 背景与问题拆解

发起人提出"项目应该可以多个角色身份"，经讨论拆解为四个彼此独立的理解方向，逐一对齐结论如下：

| # | 理解 | 结论 | 理由 |
|---|------|------|------|
| ① | 前台用户权限分级（RBAC） | **不做** | 论坛的核心活力是"人人可问可答可评"，给用户分等级会把交互做僵；后台超管 + 运营两角色（F-ADMIN-001）已覆盖管理需要；单人项目维护 RBAC 是纯负债 |
| ② | 行为型徽章（乐于助人 / offer 达人等） | **后置，写清启动条件**（006b） | 方向正确（本质是 F-GAME-001 的轻量前奏），但冷启动期无行为数据，徽章上线即空架子——现在只固化设计与门槛 |
| ③ | 校友 / 毕业身份 | **留口径**（006c） | 真实需求（"求职有路"恰需毕业生经验沉淀），但最早 2028 年才发生；现在只在 B2 名册确认时补一句口径 |
| ④ | 组织 / 社团 / 教师账号类型 | **模型预留**（006a） | 竞赛版块招新、实验室分享是真实场景，但内测期无组织入驻；今天花一个字段的钱，把"未来存在非学号账号"写进模型假设 |
| — | "提问者 / 回答者 / 分享者"角色化 | **不做**（概念澄清） | 这是**行为不是身份**——论坛天然人人都是三者，无需设计 |

## 2. 目标

| # | 目标 | 度量方式 |
|---|------|---------|
| G1 | 账号模型不再隐含"用户 = 学籍学生"的唯一假设 | `account_type` 字段落地，学籍强耦合点（核验 / 注销 / 名册补录）在设计文档中被显式标注为"仅适用 STUDENT" |
| G2 | 徽章体系到点即做、不到点不做 | 启动门槛三条（§4.3）写入本文，达成前排期 = 0 |
| G3 | 零行为变化 | 本次预留对现有全部用户与端点行为零影响（默认值即现状） |

## 3. 非目标（Non-goals）

| # | 不做什么 | 为什么 |
|---|---------|--------|
| N1 | **前台用户角色分级 / 权限体系** | 见 §1 表 ①；社区平等是产品选择，不是技术欠账 |
| N2 | **"提问者 / 回答者"等行为角色化** | 行为不是身份（§1 表尾行） |
| N3 | **本次开放任何账号类型切换能力**（端点 / UI / 注册入口） | 预留 ≠ 开通；组织认证入驻、教师邀请等流程是各自独立的功能，届时另立 PRD 评审 |
| N4 | **徽章不做等级 / 积分 / 排行** | 等级声望归 F-GAME-001（P2）；徽章只做"已获得"的布尔事实，不做比较性排名——排名在冷启动社区只制造挫败感 |
| N5 | **校友判定不建自动化流程** | 判定依赖名册更新机制（B2 未决），本期只定口径，不做毕业自动迁移的定时任务 |

## 4. 功能需求

### 4.1 功能列表与优先级

| 编号 | 功能 | 优先级 | 模块 |
|------|------|:------:|------|
| F-ACC-006a | 账号类型字段预留（`account_type`） | **P0**（字段级，随既有迁移顺带） | 账号 |
| F-ACC-006b | 行为徽章体系（设计固化 + 启动门槛） | **P2**（门槛达成前不排期） | 账号 / 互动 |
| F-ACC-006c | 校友身份口径 | **口径项**（登记入 B2，无实施量） | 账号 |

### 4.2 F-ACC-006a 账号类型字段预留（P0）

- 描述：账号模型新增 `account_type` 枚举字段，枚举值 `STUDENT`（默认）/ `ORGANIZATION` / `FACULTY` / `ALUMNI`。**本期全部账号即为 STUDENT，无任何切换能力**（N3）。
- 实施口径：
  - **不单开迁移**——随下一次账号上下文的结构变更顺带（若无，则此预留推迟到该次变更，不为它单发 `V<n>__`；如实说：单加一列的迁移成本极低，真正的价值在假设固化而非字段本身）；
  - 学籍强耦合点须显式标注"仅适用 STUDENT"：F-ACC-004（一个学号一个账号）、F-ACC-003（注销匿名化）、B2（名册补录）——dev 管理员账号（无学号）已验证"无学号账号"路径可行；
  - 主页 / 徽章等展示层本期不消费该字段。

```gherkin
Given 新用户通过学籍核验注册成功
When 查询其账号记录
Then account_type = STUDENT，且系统不存在任何修改该字段的端点与界面

Given 既有账号数据
When 迁移执行
Then 全部存量账号 account_type 默认 STUDENT，零行为变化，既有单测全绿

Given 任意已登录用户调用任何账号相关接口
When 尝试传入或变更 account_type
Then 该字段不出现在任何请求 / 响应契约中（本期纯内部预留）
```

### 4.3 F-ACC-006b 行为徽章体系（P2 · 启动门槛制）

**设计固化如下，但三条启动门槛不同时满足，禁止排期**（与 F-AI-004 门槛型同机制）：

| 启动门槛 | 数值（v0.1 提案，内测数据可修订） |
|---------|-------------------------------|
| 注册用户 | ≥ 500 |
| 全站被采纳总数 | ≥ 100 |
| 内测数据评审 | 通过（发起人签署） |

- **徽章集 v0.1**（自动授予、内容被处置时自动撤销，人工不干预）：

| 徽章 | 获得条件（提案） | 数据源 |
|------|----------------|--------|
| 乐于助人 | 回答被采纳 ≥ 10 次 | F-QA-001 采纳记录 |
| offer 达人 | 面经求职版块帖子获赞 ≥ 20 | F-FORUM-005 点赞 |
| 竞赛之星 | 竞赛交流版块帖子获赞 ≥ 20 | 同上 |
| 资源贡献者 | 学习资源版块帖子被收藏 ≥ 30 | F-FORUM-005 收藏 |

- 展示位置：个人主页身份卡徽章行（与 F-ACC-005 的级/届徽章同区）；
- 原则：只做布尔"已获得"（N4）；反作弊从简——徽章条件全由社区行为自然积累，不设申报通道。

### 4.4 F-ACC-006c 校友身份口径（登记项，随 B2）

- **建议口径（供发起人在 B2 确认时拍板）**：毕业（届别到期或名册更新判定）→ 账号转 `ALUMNI`，**保留全部社区权利**（浏览 / 发帖 / 回帖 / 被采纳）——校友经验正是"求职有路"的核心资产，只读校友是自我削弱；级/届徽章（F-ACC-005）照常展示；
- 判定机制依赖 B2 的名册更新机制（新生补录时上一届自然"毕业"），**不做自动定时任务**（N5）；
- **动作**：在下一步行动 B2 条目追加一句"名册确认时一并确认毕业账号转校友口径（F-ACC-006c）"。
