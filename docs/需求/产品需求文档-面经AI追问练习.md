## 1. 问题陈述与目标

### 1.1 问题陈述

面经的价值在"知道会被问什么"，但读面经是**被动输入**——看完 recalled 的知识与自己能不能答出来是两回事。校外的模拟面试产品（牛客面经模仿、各类 AI 面试工具）要么不垂直、要么收费；校内社区手里握着**本校学长学姐的真实面经**，这是天然的高质量追问素材库：

- 把"读面经"升级为"拿这份面经练"——AI 从面经正文提取面试考察点，生成面试官视角的追问，用户对照自查；
- 给面经求职版块一个**差异化的存在理由**：在这里不只看经验，还能练；
- 成本结构天然友好：追问由帖子内容派生，**可缓存、可复用**——同一份面经的追问全站共享一份。

### 1.2 目标

| # | 目标 | 度量方式（见第 6 节） |
|---|------|-------------------|
| G1 | 面经读者愿意用 | 面经帖访问用户中使用渗透 ≥ 10% |
| G2 | 生成的追问被认为有用 | 👍 有用率 ≥ 60% |
| G3 | 成本可控 | 缓存命中率 ≥ 90%（含首次生成摊薄）；月成本 ≤ 10 元 |

## 2. 非目标（Non-goals）

| # | 不做什么 | 为什么 |
|---|---------|--------|
| N1 | **不做多轮模拟面试对话**（AI 追问 → 用户答 → AI 再追问的循环） | P2；多轮对话的上下文管理与成本是另一个量级，先验证单轮追问有没有人用 |
| N2 | **P0 不做用户作答与 AI 点评** | 作答 + 点评（P1）价值更高但复杂度陡增（点评质量、防误导）；先交付"生成追问自查"这个最小闭环 |
| N3 | **不生成"标准答案"** | 面试题的答案随岗位/版本变化，AI 给出错误标准答案的误导风险 > 价值；自查引导回社区讨论（AI 只提问，不回答） |
| N4 | **不对面经求职以外的版块开放** | 技术问答帖是"求助"不是"经历复述"，追问生成的素材属性完全不同；扩展需另行评审 |
| N5 | **不做语音面试 / 计时器等拟真交互** | 拟真是锦上添花，P0 只验证"追问内容有没有用" |
| N6 | **不对机审未通过或过短（正文 < 200 字）的面经开放入口** | 素材质量兜底：太短的面经生成不出有效追问，机审兜内容合规 |

## 3. 用户与场景

### 3.1 用户故事

- 作为一名**准备找实习的大三学生**，我读完一份 Java 后端面经后想点一下"模拟追问"，看看基于这份面经 AI 会追问我什么，以便对照自查哪些点答不上来；
- 作为一名**面经作者**，我希望 AI 追问是基于我的正文内容生成的（而不是泛泛的"请介绍一下项目"），以便这份练习对读过这篇面经的人有针对性；
- 作为一名**多次练习的用户**，我想对同一份面经"再来一组"换一批追问，以便覆盖更多考察点——但要有限流，防止我刷到停不下来（也防成本失控）；
- 作为一名**访客**，我看到的面经追问应该是社区共享的同一份（而不是每人生成各自的），以便热门面经的成本被摊薄。

### 3.2 边界场景（必须覆盖）

- 首次生成进行中 → 显示加载态；生成失败 → 区块显示"暂无法生成，稍后再试"，**不阻塞面经正文阅读**；
- 第二个用户访问同一面经 → 直接命中缓存，**秒出**（不做等待动画）；
- 正文超长（> 4000 字）→ 截断前 4000 字生成（提示词声明"以下为面经节选"）；追问质量不受实质影响（考察点集中在前半部分是面经常见形态，如实接受该局限）；
- "再来一组"达到当日限流 → 按钮置灰并提示"今日次数已用完，明日再来"；
- 面经被编辑（F-FORUM-007 上线后）→ 缓存失效，下次访问异步重算；
- 面经被删除 / 机审拦截 → 缓存与入口一并下线；
- 追问内容含违规 → 该次生成作废并计数（LLM 输出同样过机审或敏感词过滤，成本考虑用轻量敏感词兜底 + 举报入口兜底）。

## 4. 功能需求

### 4.1 功能列表与优先级

| 编号 | 功能 | 优先级 | 模块 |
|------|------|:------:|------|
| F-AI-003a | 追问生成与缓存（每帖一份全站共享） | **P0** | AI 辅助（`module/ai`） |
| F-AI-003b | "再来一组"限流强刷新 | **P0** | AI 辅助 |
| F-AI-003c | 有用性反馈与埋点 | P0 | 数据 |
| F-AI-003d | 用户作答 + AI 点评 | P1 | AI 辅助 |

### 4.2 功能详情与验收标准

**F-AI-003a 追问生成与缓存（P0）**

- 描述：面经求职版块帖子详情页提供"模拟追问"区块。首次访问触发异步生成 **3~5 个面试官视角追问**（基于帖子正文，提取考察点后改写为追问句式），结果落库**每帖一份全站共享**；后续访问直接读缓存。
- 业务规则：
  - 入口条件：帖子属于面经求职版块、正文 ≥ 200 字、机审已通过；
  - 生成内容为**追问列表**（每条 ≤ 50 字），不含答案——AI 只提问不回答（N3）；
  - 正文 > 4000 字截断策略见 §3.2；
  - 失败静默：生成失败不影响正文阅读，区块显示重试入口；
  - 受保护端点（需登录才能触发首次生成与强刷新；读缓存可与正文同权限口径）。

```gherkin
Given 面经求职版块存在正文 ≥ 200 字、机审通过的帖子且尚无缓存
When 已登录用户首次点击"生成模拟追问"
Then 异步生成 3~5 条追问并落库，区块展示追问列表（不含答案）

Given 该帖已有缓存追问
When 任意用户（含未触发生成者）访问该帖详情
Then 区块直接展示缓存追问，无生成等待

Given 面经正文 150 字
When 用户访问详情页
Then 不展示"模拟追问"入口

Given 生成服务不可用
When 用户点击生成
Then 区块提示"暂无法生成，稍后再试"，面经正文阅读不受影响
```

**F-AI-003b "再来一组"限流强刷新（P0）**

- 描述：已缓存追问下方提供"再来一组"——忽略缓存重新生成一组并覆盖该帖缓存（覆盖前旧组对正在查看的用户保持可见至刷新）。
- 业务规则：**每用户每日 5 次**强刷新限流（Redis 计数，与验证码限流同套基础设施）；限流不约束普通浏览（缓存读取无限流）。

```gherkin
Given 用户当日已强刷新 5 次
When 再次点击"再来一组"
Then 按钮置灰并提示"今日次数已用完"，当日不再恢复

Given 用户 A 强刷新生成了新一组追问
When 用户 B 随后访问该帖
Then B 看到的是新一组（缓存为全站单份，最新覆盖旧）
```

**F-AI-003c 反馈与埋点（P0）**

| 事件 | 触发时机 | 关键属性 | 支撑指标 |
|------|---------|---------|---------|
| mockq_view | 追问区块展示（含缓存命中） | post_id、来源（缓存/新期生成） | 渗透分母、缓存命中率（G3） |
| mockq_generate | 触发首次生成 / 强刷新 | post_id、是否强刷 | 成本计量 |
| mockq_feedback | 用户点 👍 / 👎 | post_id、是否展开 | 有用率（G2） |
| mockq_entry_show / mockq_entry_click | 入口展示 / 点击 | post_id | 使用渗透（G1） |

**F-AI-003d 作答 + AI 点评（P1，本文只预留不展开）**

- 预留设计约束：作答文本需过机审；点评只对**用户自己的作答**生成、不公开（避免公开区出现 AI 生成的低质答案污染社区）；成本按次计、每用户每日限流。P1 立项时另行补充详设与评审。

## 5. 技术约束与依赖

- `module/ai` 与 LLM 网关由 F-AI-001 / F-AI-002 建立，本功能**纯复用**（新用例 + 新缓存表，无新基础设施）；
- 追问缓存表 `ai_mock_question`（post_id 唯一、内容 JSON、生成时间），走 `V<n>__` 迁移；
- 正文外发第三方模型（最高 4000 字/次）：面经为发布者**公开自愿发布**的内容，隐私政策披露"面经正文将发送至第三方模型服务用于生成练习追问"；**不携带用户身份**；
- 机审联动：LLM 输出以轻量敏感词过滤兜底 + 追问区支持举报（复用 F-SAFE-002）。

## 7. 发布计划与开放问题

- **排期**：增量约 **1 天**；**排位于 F-AI-001（检索版）交付之后**——共享其 module/ai 管道，且先验证"AI 区块嵌入内容页"的交互模式成立；
- **前置**：面经求职版块有真实内容（内测种子内容 ≥ 20 篇面经，否则入口形同虚设——种子内容属发布计划 §7 既有项）。

| # | 开放问题 | 责任人 | 阻塞性 |
|---|---------|--------|--------|
| Q1 | 追问条数（3~5）与单条字数（≤ 50）定稿 | 产品 + 开发 | 阻塞开发 |

| Q3 | 未登录用户是否可读缓存追问（当前设计：可读，与正文同口径；触发生成需登录） | 产品 | 评审时定 |
| Q4 | P1（作答 + 点评）的启动条件 | 产品 | F-AI-003a 数据评审时 |
