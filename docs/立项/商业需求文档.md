## 1. 项目背景与痛点

计算机类专业是全国高校招生与在校规模最大的专业类之一（在校生数以百万计，具体数据待核实），但专业学习与成长过程中的**交流诉求**长期缺乏好的承载：

- **"读得到内容，得不到交流"**：CSDN、博客园、掘金等内容平台以"消费文章"为主，提问与讨论氛围弱，初学者问题常石沉大海；
- **初学者求助难**：环境配置、报错排查、方向选择等入门问题，搜索引擎结果碎片化、时效差，知乎等通用社区缺少学生视角的针对性回答；
- **经验信息散乱且不可沉淀**：学习路线、竞赛（ACM / 蓝桥杯 / 数学建模）、考研保研、实习面经等信息散落在 QQ 群、公众号、网盘链接中——不可搜索、不可沉淀、质量参差；
- **同伴与组队难**：课程大作业、竞赛、开源项目想找同学组队，缺少专门场所；牛客等平台偏求职全民化，缺少"在校生回答在校生"的平等互助氛围。

## 2. 目标用户

**核心用户**：计算机类专业在校本科生与研究生（计科、软件工程、网络安全、人工智能、大数据、电子信息等）；延伸覆盖辅修 / 转码学生。

| 画像 | 特征 | 核心诉求 | 典型场景 |
|------|------|---------|---------|
| A：初学者（大一大二） | 刚入门，报错与路线问题多 | 快速获得解答、找到学习路线与基础资源 | 搜"Redis 配置报错"、问"先学前端还是后端" |
| B：进阶者（大三 / 研究生） | 面临实习、考研、竞赛选择 | 面经与经验、项目实战交流、组队备赛 | 看同专业实习面经、找 ACM 队友 |
| C：组织者 / 爱好者 | 技术社团成员、实验室学生、竞赛队长 | 分享沉淀、组织活动、建立影响力 | 整理课程攻略、发布竞赛组队帖 |

## 3. 市场机会

- **用户规模**：计算机类专业招生与在校规模居各专业前列，且该人群学习天然依赖互联网，是线上社区的高适配人群；
- **竞争格局**：牛客（偏全民求职）、CSDN / 掘金（偏内容消费与从业者）、知乎（泛化问答）、各校 QQ / 微信群（碎片化不可沉淀）——**"计算机专业学生"这一垂直人群缺少专门的交流社区**；
- **机会窗口**：以"学生视角 + 专业垂直 + 板块化沉淀"切入；与泛校园社交相比，内容需求高频刚需、可复用可沉淀，冷启动难度更低。

## 4. 产品定位与价值主张

**一句话定位**：面向计算机专业大学生的垂直交流论坛——**问有所答、学有同伴、求职有路**。

**差异化**：

1. **专业垂直**：版块、标签、内容全部围绕计算机学习与成长组织，不是泛校园闲聊社区；
2. **学生视角**：在校生回答在校生的问题，平等互助，区别于从业者社区的经验门槛；
3. **结构化沉淀**：问答可采纳最佳答案、帖子可搜索可沉淀，区别于群聊的一次性信息流。

## 5. 核心功能方向（MVP 候选）

| 功能方向 | 说明 | MVP 候选 |
|---------|------|:-------:|
| 版块体系 | 固定版块：技术问答 / 学习资源 / 面经求职 / 竞赛交流 / 课程交流 / 闲聊灌水 | ✅ |
| 发帖与回复 | 标题 + Markdown 正文（含代码块语法高亮）+ 标签，楼层式回复 | ✅ |
| 问答采纳 | 技术问答帖可采纳最佳答案 | ✅ |
| 互动 | 点赞、收藏、站内通知 | ✅ |
| 站内搜索 | 标题 + 标签搜索 | ✅ |
| 内容安全 | 机审 + 举报 + 处置（合规必需，见可行性报告第 4 节） | ✅ |
| 运营后台 | 登录权限、内容处置台、举报工单 | ✅ |
| **学籍核验注册** | **学号 + 姓名比对，限重庆工程学院在校学生（v0.3 由 P1 提升为 P0）** | **✅（P0）** |
| 私信 | — | ❌（P1） |
| 组队广场 | 课程 / 竞赛 / 开源项目组队 | ❌（P2） |
| 等级声望体系 | 内容质量激励 | ❌（P2） |
| 匿名发帖 | 面经板块可选匿名 | ❌（P2） |

## 6. 商业价值与盈利模式（远期）

> MVP 阶段不设盈利目标，优先验证社区活跃与留存。远期候选：

- 校招 / 企业合作：技术岗位招聘信息、内推板块（需严格审核）；
- 学习资源与课程合作分成；
- 增值会员（高级搜索、资源包等）。

## 7. 成功指标（假设值，待评审）

| 指标 | 目标值 | 说明 |
|------|-------|------|
| 北极星指标 | 周活跃用户中内容贡献者（发帖或回帖）占比 ≥ 30% | 社区"活"的本质是贡献而非浏览 |
| 问答健康度 | 技术问答版块提问 48 小时内获回复比例 ≥ 70% | 问答社区的生命线指标 |
| 试点注册渗透率 | ≥ 25%（重庆工程学院计算机专业学生，草案） | **单校范围，分母远小于原 1~2 所高校方案，故渗透率目标上调** |
| 留存 | 7 日 ≥ 20%，30 日 ≥ 10% | 内容社区留存基准（草案） |
| 内容供给 | 日均新帖（含回复）≥ 30 条（草案） | 冷启动健康度，按单校规模下调 |
| 学籍核验通过率 | 内测期 ≥ 90% | **名册覆盖率的直接观测项（章程 R7）** |

## 8. 主要风险与应对

| 风险 | 说明 | 应对思路 |
|------|------|---------|
| 冷启动内容空 | 无内容无用户，社区死寂 | 种子内容先行（学习路线、面经合集 ≥ 200 帖）+ 高校技术社团 / 竞赛队 / 实验室合作 + 邀请制内测 |
| 内容质量劣化 | 低质灌水驱逐优质回答 | 版规明确 + 机审 + 举报处置；后期以等级声望（P2）引导质量 |
| 大平台竞争 | 牛客 / CSDN / 知乎部分替代 | 垂直学生视角 + 板块化沉淀 + 同学关系网络建立差异 |
| 内容合规 | UGC 平台的审核义务与平台责任 | 机审 + 人工巡查 + 举报处置全链路（详见可行性报告第 4 节） |
| 留存不达标 | 内容社区留存普遍偏低 | 北极星 + 问答健康度双指标跟踪，阶段门机制止损复盘 |

## 9. 结论与建议

建议**立项通过**（定位已按发起人确认调整为计算机专业学生交流论坛）。**MVP 仅在重庆工程学院范围内试点**（v0.3 锁定），验证核心假设：**"提问有回复 + 内容能沉淀"能否形成留存**。若 48 小时回复率或留存连续不达标，按阶段门机制暂停扩张、复盘定位问题。

> 本期明确不外扩至其他高校。单校样本量有限，指标结论须标注"单校样本"后再决定是否扩展（章程 R8）。
