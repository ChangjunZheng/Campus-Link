## 1. 技术可行性 — 结论：可行

- **产品形态**：**Web 网站优先**（桌面端为主 + 响应式适配移动端）。理由：论坛的核心场景是长文阅读、代码阅读与键盘输入，Web 体验最自然；且无需应用商店审核与小程序类目资质，上线链路最短。微信小程序 / 原生 App 留作后续评估（P2）；
- **技术栈**：前端 Vue / React 生态 + 后端 Spring Boot 或 NestJS + PostgreSQL / MySQL + Redis，全部为主流成熟方案，无稀缺技能依赖；**设计阶段已定稿为 Vue 3 + Spring Boot + Java + MySQL 8 + Redis 7**（见[技术方案](../设计/技术方案.md) ADR-003 / ADR-009；后端框架 2026-08-30 由 NestJS 反转为 Spring Boot，2026-08-31 升级至 Spring Boot 4.1 + JDK 21，对应 [CR-004 / CR-007](../变更日志/变更台账.md)）；
- **关键技术点**：
  - **Markdown 渲染安全**：帖子正文渲染必须采用标签白名单过滤，防存储型 XSS——这是论坛类产品的安全生命线（PRD 已列入非功能需求）；
  - **搜索**：MVP 用数据库全文 / 前缀匹配实现标题 + 标签搜索，规模上来后再引入 Elasticsearch，避免过早增加组件复杂度；
  - **内容审核**：接入第三方内容安全服务（如阿里云内容安全、微信内容安全接口），不自研审核算法；
- **复杂度对比**：无实时 IM、无音视频、无推荐算法，技术复杂度显著低于社交类产品；
- **团队要求**：全栈 1~2 人 + 内容运营即可启动；
- **技术风险评级：低**——无自研算法或底层攻关，全部风险点为常规工程问题。

## 2. 经济可行性 — 结论：MVP 成本可控

| 成本项 | 说明 | MVP 期量级（草案） |
|-------|------|------------------|
| 人力 | 开发 + 产品 + 内容运营 | 主要成本，按团队实际折算 |
| 云资源 | 服务器、数据库、对象存储、CDN | 数百 ~ 千元 / 月 |
| 第三方服务 | 内容审核、邮件 / 短信验证码 | 数百 ~ 千元 / 月（邮件验证码成本远低于短信） |
| 资质与备案 | 域名、ICP 备案 | 一次性，千元内（不含代办费） |

- Web 首发无需 App 备案与应用商店相关成本；无 IM SDK 采购成本；
- 盈利：MVP 无盈利要求（见 BRD 第 6 节，盈利为远期方向）；
- **经济结论**：主要成本为人力，现金支出控制在千元 / 月量级，可承受。

## 3. 运营可行性 — 结论：可行，但内容运营是成败关键

- 论坛的历史败因多数是冷启动内容与运营问题而非产品问题，**必须配置明确的内容运营人力**，不可纯线上冷启动；
- **种子内容先行**：上线前预埋 ≥ 200 帖优质内容（学习路线、面经合集、课程攻略、资源整理），保证首批用户"有东西可看、有帖子可回"；
- **合作渠道**：与高校技术社团、ACM 集训队、实验室学生团队合作，作为首批种子用户与内容供给方；
- **节奏**：邀请制内测（100~200 人）→ 试点高校计算机专业学生社群开放 → 数据达标后扩展；版主机制在 P1 阶段引入。

## 4. 法律与合规专项 — 结论：路径清晰，无硬性障碍，合规成本必须计入

论坛属于典型的 UGC（用户生成内容）服务，逐项核对如下：

| 事项 | 要求 | 本项目动作 |
|------|------|-----------|
| 网络实名制（《网络安全法》） | 网络服务须实现后台实名 | 邮箱 / 手机号注册 + 后台实名；前台展示昵称 |
| 《个人信息保护法》 | 告知同意、最小必要收集、用户权利保障 | 上线隐私政策；需求阶段产出个人信息收集清单并评审；提供账号注销 |
| 未成年人保护 | 实名校验 + 未成年人使用策略 | 注册环节年龄校验；策略在需求阶段确认 |
| UGC 内容治理（《网络信息内容生态治理规定》） | 平台对用户生成内容负有审核与处置义务 | 先机审后展示 + 人工巡查 + 举报处置流程 + 违规账号处置机制（列入 MVP 范围） |
| ICP 备案 | 域名须完成 ICP 备案 | 上线前完成 |
| 平台资质 | 仅在发布小程序 / App 时需要相应资质 | Web 首发暂不涉及；后续端形态确定后再核对（需法律意见确认） |

- 合规结论：无硬性障碍，但备案、审核机制、隐私政策是**上线前置条件**，须排入里程碑（已列入项目章程目标 G3）。

## 5. 风险汇总

| ID | 风险 | 维度 | 等级 | 应对 |
|----|------|------|------|------|
| R1 | 冷启动内容供给不足 | 运营 | 高 | 种子内容先行 + 技术社团合作 + 邀请制内测（见 BRD 第 8 节） |
| R2 | 合规动作延误上线 | 合规 | 中 | 备案与审核机制纳入里程碑并行推进 |
| R3 | 内容质量劣化（灌水、低质问答） | 运营 | 中 | 版规 + 机审 + 举报处置；P2 声望体系引导 |
| R4 | 留存假设不成立 | 商业 | 中 | 北极星 + 问答健康度双指标跟踪，阶段门止损 |
| R5 | 搜索与列表性能随规模下降 | 技术 | 低 | MVP 数据库方案 + 索引设计预留，规模触发点后引入 ES |

## 6. 综合结论

**有条件可行**。条件：

1. 合规动作（ICP 备案、隐私政策、内容审核机制）纳入 MVP 里程碑，作为上线前置条件；
2. 内容运营人力与种子内容（≥ 200 帖）在试点上线前到位；
3. 北极星（贡献率）与问答健康度（48h 回复率）双指标按 BRD 第 7 节跟踪，不达标时按阶段门机制止损复盘。
